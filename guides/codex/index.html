Codex 中转站怎么选、怎么配？

Codex CLI 是 OpenAI 推出的命令行编程助手，不少国内开发者会通过中转站接入它。本站目前收录的 551 家中转站里，有 316 家提供 codex 相关模型或分组——这篇文章讲清楚选站要注意什么、怎么配置环境变量。

Codex CLI 是什么，为什么要用中转站

Codex CLI 是跑在终端里的编程助手，能读写本地代码、执行命令、辅助调试。它调用的是 OpenAI 的模型接口，走官方渠道通常需要境外支付方式，也要面对海外接口在国内访问的稳定性问题。中转站把这一层门槛去掉了——用人民币充值，拿到一个 base_url 和 key，改两个环境变量就能接入，这也是为什么很多人第一次接触中转站，就是从想用 Codex CLI 开始的。

Codex 专属的一个注意点

不少中转站会专门开一个「Codex 专用」分组，价格往往比通用 GPT 分组更划算，但这类分组通常只认官方 Codex CLI 客户端发出的请求（后台会检测请求特征，比如 User-Agent），Cursor、Cline 这类第三方编辑器接进去大概率会报错或被直接拒绝。买之前一定要问清楚：这个分组支不支持我要用的客户端，别等充值之后才发现用不了。

怎么配置

Codex CLI 通过两个环境变量读取接入信息，设置好之后重新打开终端或者 source 一下配置文件即可生效。

export OPENAI_BASE_URL="https://站点域名/v1"
export OPENAI_API_KEY="你的key"

设置完成后，跑一个简单的任务（比如让它读一个本地文件并总结）验证是否正常返回，就说明配置生效了。如果想固定写入配置文件，加到 shell 的启动脚本（如 .zshrc 或 .bashrc）里即可，注意换终端窗口或重启终端后才会生效。

选站建议

1

有没有明确标注 Codex 分组

有些中转站会单独列出「Codex 专用」或「Codex 分组」，说明它对这条通道做过针对性适配（比如只认官方 CLI 的请求特征）。没有单独标注的站点，不代表用不了，但接入前最好先问一句。

2

价格是否透明

同样是 Codex 相关模型，不同渠道分组的价格可能差好几倍。透明的站点会写清楚这是官转还是订阅拆分渠道，价格差距背后的原因也就说得通。

3

渠道来源说不说得清

问客服或看文档，能不能说清楚这个 Codex 分组背后接的是什么渠道。含糊其辞、只说「稳定可用」但不解释来源的，谨慎一些。

常见问题

为什么有些中转站的模型列表里有 Codex，但我在 Cursor 里用不了？

部分中转站的 Codex 专属分组只识别官方 Codex CLI 客户端发出的请求特征（比如 User-Agent），第三方编辑器或工具接进去可能直接报错或被拒绝。这类限制是渠道本身决定的，不是配置错了，购买前最好先确认该分组是否支持你要用的客户端。

本站说的 316 家「支持 codex」具体指什么？

指的是本站收录的 551 家中转站里，有 316 家在其模型列表或分组说明中提供了 codex 相关的模型或专属分组，这是基于本站实际数据统计的结果，具体每家站点支持的范围和限制仍需以该站文档为准。

Codex 中转站和普通 GPT 中转站是一回事吗？

接口层面很多是共用的（都兼容 OpenAI 格式），但 Codex 相关的分组往往针对代码生成场景做了模型选型或客户端限制上的区分，所以中转站通常会把它单独列出来，价格和可用范围也可能和普通 GPT 分组不一样。
